# RepoFlow 当前规格

来源：2026-10-09 用户创建项目及截图反馈，2026-10-10 独立详情页与完整 README 追加要求。实现使用 GPT-6.1 Sol / xhigh 执行代理，没有委派 Luna。

目标：按 YouTube 的内容发现交互浏览真实 GitHub 开源项目，通过浏览器跳转 GitHub 登录，支持偏好推荐、快捷收藏与真实 Star。

## 验收要求

1. 顶部搜索、侧栏、横向分类标签与响应式项目网格；无宣传区、演示数据及演示切换。
2. 列表与统计通过 GitHub API 获取，封面及头像使用实际仓库资源；失败可重试，不返回伪造内容。
3. 搜索支持普通关键词及 `topic:`、`language:`；分类、时间窗口、连续加载与手动加载可用。
4. 详情、稍后再看、收藏、历史、不感兴趣和偏好可用；本地状态按访客与每个真实账号隔离并持久保存。
5. 点击登录直接进入浏览器跳转。首次本机接入可在 GitHub 页面确认创建应用，服务端自动保存凭据，不要求用户编辑文件。后续直接跳转授权。
6. Token 不进入前端；Star / 取消 Star 由服务端调用 GitHub，失败不伪装成成功。
7. TypeScript / 生产构建、API 风险测试、浏览器关键流程和移动端布局验证通过。真实账号授权与写入只在用户本人操作时发生。
8. 修复用户实际遇到的 loopback webhook 注册失败；通过省略无需使用的 webhook 配置注册。
9. 登录后自动综合历史 Star 与本人公开仓库的主题、语言进行候选检索和排序，显示实际分析数量、范围与推荐依据；保留手选偏好和账号隔离。
10. 点击封面或标题进入 `/project/:owner/:repo` 独立详情页，支持直接访问、刷新、新标签页、前进后退及回到列表浏览位置；不再以悬浮弹窗显示项目详情。
11. 页面下方展示实际完整 README，支持 GFM 表格、代码、相对图片与链接、目录和安全的折叠 HTML；缺失或读取失败分别提示且可重试，不静默截断。
12. 详情操作区提供稍后再看、Star、复制站内链接和显著的打开原仓库按钮，复用账号隔离与真实 Star 行为；手机布局可换行且无页面横向溢出。
13. 详情页打开后在独立框体自动生成一级技术来源图谱，圆形进度反映已完成阶段；另有 `/graph` 工作台供独立输入仓库使用。
14. README credits / citations 等引用与显式 GitHub 依赖地址提供直接证据；主要贡献者、明确维护者及其相似公开项目提供关联证据，人员角色与采样范围可查看。
15. 直接引用置于内档，开发者关联项目置于外档；每档按标签 Jaccard 重合度降序、Star 降序稳定确定远近。用户可对单个节点手动继续追溯，自动不超过一级。
16. 使用有请求预算、超时、队列限制和公开结果持久缓存的异步方案；失败、限流与部分结果可辨认，不读取私有源码或将标签相似推断成真实引用。具体合同见 [图谱规格](graph-contract.md)，设计取舍见 [ADR 0005](adr/0005-technical-provenance-graph.md)。
17. 图谱节点面积随真实 topic 重合度增加，至少 30% 常驻名称；语言回退与无标签按最小尺寸。选择节点突出一阶相连邻域并可居中，查看全图恢复整体关系；手动展开分支独立布局，父路径与层级在面板说明。补充设计见 [ADR 0008](adr/0008-graph-branches-and-camera.md)。
18. README 的 Related、版权与许可证归属段落也纳入仓库链接识别。仅对明确的技术上下游绘制“来源 → 使用方”箭头；普通引用、关联或冲突关系为无向虚线，保留原文、行地址与判据。采集路径与技术方向独立，扩大识别范围不自动增加递归层数或请求预算。见 [ADR 0009](adr/0009-readme-evidence-and-technical-flow.md)。
19. 可按关注者分别调整其兴趣与社交推荐的正常模式权重，默认 1 倍、0 倍忽略；基于真实公开动态并说明现有采样范围，设置按账号隔离持久保存。
20. 仓库页前台累计阅读严格超过 3 分钟，或严格超过 1 分钟并打开对应原仓库，给予相关标签少量加权；隐藏 / 失焦时间不计，账号切换隔离，同账号同仓库 24 小时最多一次。
21. 提供正常、换换口味和完全随机模式开关。换口味默认目标约 50% 已关注方向 / 50% 其他方向，允许候选短缺互补并保留后续比例实验空间；完全随机在实际公开检索候选内抽取。两种探索模式不按个人兴趣排序，但继续积累偏好行为并遵循屏蔽 / 已知项目过滤。见 [ADR 0010](adr/0010-recommendation-controls-and-reading-signals.md)。
22. Star 写入的非限流权限拒绝可通过同一用户身份的固定 GraphQL 操作有界兼容；真正拒绝保留原状态并提供 GitHub 原仓库入口，不以反复登录代替权限诊断。见 [ADR 0011](adr/0011-star-write-compatibility.md)。
23. 本次页面运行内，各推荐模式分别保存列表、分页与滚动进度；返回首页或切回已加载模式不重新搜索。手动换批替换对应模式，主动滚动可继续分页；刷新页面视为再次启动。见 [ADR 0012](adr/0012-resumable-feed-and-graph-workspaces.md)。
24. 技术图谱保留上次合并结果、手动追溯、选中节点和视角；返回已有根或独立工作台不自动重新分析。主动搜索 / 重新分析更新结果，账号隔离及请求预算保持。
25. GitHub App 的实际 Star 权限拒绝可在本机通过 OAuth App 网页向导连接替代授权方式。用户在 GitHub 注册 / 授权，网页提交连接信息，无需编辑文件；校验 scope 和身份成功后才保存独立 OAuth 连接。权限范围、失败状态与来源优先级明确，原 App 凭据保持不变。见 [ADR 0013](adr/0013-oauth-connection-for-public-stars.md)。

最初的演示模式与手动 OAuth 配置方案已被取代，历史保留在 [ADR 0001](adr/0001-github-auth-and-recommendations.md)；当前项目流见 [ADR 0002](adr/0002-youtube-feed-and-github-app.md)，独立详情见 [ADR 0004](adr/0004-project-pages-and-full-readme.md)，结果见 [验收](acceptance.md)。
