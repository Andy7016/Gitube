# ADR 0010：关注者权重、有效阅读与探索模式

日期：2026-10-11。状态：已采纳。补充 [ADR 0006](0006-gitube-frontend-integration.md) 的推荐交互；不替代 [发现价值调研](../recommendation-research.md) 中尚待研究的热门项目降权方案。

## 来源与目标

用户要求先提交当前进度，再增加特定 following 的兴趣权重、仓库页逗留信号，以及“换换口味”和“完全随机”模式。用户随后明确：50% / 50% 是换口味的当前合理目标，后续仍留实验与讨论空间，不要求每批严格各半。

## 决定与理由

- 先以中性 noreply 身份创建本地检查点 `4ee6dd3`，保存认证、详情与有证据的技术图谱。后续推荐改动独立于这个检查点，便于比较和恢复。
- 在偏好设置中按真实关注动态中的账号调整 0–3 倍权重，默认 1 倍。其已采样 Star 的 topic / 语言为正常画像提供有界贡献，并影响社交推荐的优先级；0 倍完全不参考该人。贡献按人归一，不让样本多的人天然获得更多权重。原始关注动态频道继续展示其动态，权重不代表取消 GitHub 关注。
- 沿用现有前 12 位关注用户、每位最近 6 个公开 Star 的采样，不增加 GitHub 权限或抓取范围。界面只列出本次实际读到有效动态的账号，说明数量与局限。权重按当前账号存于本地，不读取关注者私有项目。
- 仅累计仓库详情页处于可见且获得焦点的前台时间，使用单调时钟；隐藏、失焦、离开页面暂停。累计严格超过 3 分钟，或严格超过 1 分钟并打开本页对应原仓库时，写入小幅 `dwell` 信号，初始权重 0.3。单账号同仓库 24 小时最多一次，不因重复点击或后台挂页不断加权。最多保留 1000 个活跃去重项；满额时暂停新信号，避免驱逐有效记录后重复计权。
- 原仓库按钮保留浏览器新标签与键盘 / 中键行为。作者主页、复制 clone 命令或其他项目链接不作为本项目外跳信号。路由和账号切换结束本次计时，写入时再次核对账号，禁止旧页面信号落入新账号。
- 首页和设置共享三个互斥模式：正常推荐、换换口味、完全随机。正常模式延续已有兴趣 / 热度 / 活跃度排序，同时加入关注者和阅读信号。换口味按明确手选兴趣展开的 topic 将实际候选分为“已关注方向”和“其他方向”，默认目标约各半；比例集中定义为 `TASTE_FAMILIAR_SHARE = 0.5`，引擎构造参数 `tasteFamiliarShare` 可供实验调整。某一侧不足时另一侧补足，不为满足比例丢掉全部可用结果。
- 两种探索模式在候选池内随机选择，不采用个人兴趣评分和社交固定插槽；完全随机也不要求候选匹配手选方向。已 Star、本人仓库、不感兴趣、屏蔽和最近曝光的过滤继续生效。没有可用手选兴趣时禁用换口味并回到正常推荐。
- GitHub 没有此处可用的全库随机抽样接口，采用随机创建时间窗、Star 区间和排序变种进行有界召回，再在真实候选内洗牌。每批最多 3 轮，每轮最多 8 个搜索条件；不宣称全 GitHub 仓库等概率，也不以演示项目补齐候选。
- 模式拥有独立的分页游标与会话曝光状态，共享本地浏览反馈和最近曝光过滤。两种探索模式下的打开、收藏、Star、有效阅读等照常累计，回到正常模式时使用。切模式、修改兴趣 / 权重或刷新会使旧在途结果失效，阻止其提交列表、游标或曝光状态。
- 继续兼容 `LibraryData.version:1`：新增字段缺失时补默认值，过滤非法模式、权重与时间戳。重置推荐恢复正常模式 / 默认关注者权重并清理阅读去重与各模式游标，保留收藏、稍后再看与历史。

## 验收与边界

验证真实分类比例与短缺补足、随机模式不按画像排序、过滤和游标隔离、关注者权重的线性与归零、旧存储兼容与账号隔离；使用可控时钟验证严格阅读阈值、后台暂停、外跳和页面清理。浏览器检查模式切换、慢响应隔离、滑杆持久化、两种探索模式继续记录行为、手机布局和既有业务回归。结果追加到 [验收记录](../acceptance.md)。

阅读信号表示本地兴趣倾向，不证明用户实际读懂或喜欢项目；不尝试跟踪原 GitHub 标签页的阅读。随机模式受 GitHub 检索可达范围和搜索排序影响，默认比例与 0.3 权重是可审阅的初始策略，尚不是经效果实验确定的最优参数。
