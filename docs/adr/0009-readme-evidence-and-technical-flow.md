# ADR 0009：README 链接证据与技术流向

日期：2026-10-11。状态：已采纳。补充 [ADR 0005](0005-technical-provenance-graph.md) 的采集语义与 [ADR 0008](0008-graph-branches-and-camera.md) 的图谱呈现。

## 来源与目标

用户指出 Related、版权声明也会列出相关仓库，README 中的项目可能是当前项目的技术来源。需要扩大链接识别，并使箭头表达能从原文核实的上下游关系，避免把“发现了一个链接”画成“当前项目影响了它”。

## 决定与理由

- 继续只采集明确的 GitHub 仓库地址，并通过 GitHub API 核实公开项目；不按名称猜仓库，不额外抓取任意外部页面。覆盖 Markdown 内联与引用式链接、HTML 链接，以及技术来源段落中的裸地址。新增 Related / See also / Alternatives 与版权 / 许可证 / Attribution 等语义段落。
- 每条文档证据保留 README 行地址、原文片段、实际目标仓库 URL、关系和判定理由。按链接所在局部句子、列表项或表格内容分析，并结合标题语境，防止同一长列表里其他项目的描述污染当前链接。
- 明确的依赖、基于、衍生、移植、采用或灵感来源描述可将目标判为上游；明确列出的使用者或下游项目可将目标判为下游。实际 GitHub 依赖声明也支持上游判断。这些是可解释的文档规则，不是对完整源码依赖图的证明。
- Credits、Citation 或版权标题本身不证明技术方向；Related 只证明关联。否定、比较、关系冲突或证据不足时保留无向关系。明确方向与普通提及合并后仍保留明确依据；同时出现上下游或不确定证据时降为待核对，不凭 Stars、topic 重合度或人员身份推断方向。
- 箭头统一表达“技术提供方 → 使用或衍生方”。上游目标的箭头朝当前分析项目，下游目标的箭头朝目标项目；普通提及、关联和待核对关系使用无箭头虚线。来源面板说明方向与判据。无箭头的名称引线继续只用于标签定位。
- `GraphEdge.source/target` 继续记录“分析项目 → 发现项目”的采集路径；新增 `relation` 表示技术语义。布局、手动展开、层级和防环仍使用采集路径，渲染使用技术流向，避免反转箭头时破坏现有图谱结构。
- 关系合并由前后端共享的纯函数处理；公开 DTO 对新增字段采用白名单，重新从证据计算边关系。结构版本保留 `version:1`，新结果增加 `semanticsVersion:2`；旧缓存可安全读取，但不能冒充已经完成新版解析，访问时重新运行有预算的一级分析。
- 新增关系图例后，内嵌画布变矮，验收暴露四节点小图在固定 17px 根节点附近重叠的问题。补充 ADR 0008 的摄像机规则：适配时只为圆点与光晕留边，名称由既有独立避碰逻辑放置，避免重复扣除名称空间；同时以实际圆间距约束最小缩放和聚焦密度。根节点保持固定尺寸，透明光晕不拦截圆点点击。

## 边界与验收

自动一级、24 个文档 / 依赖目标、4 位相关人员、40 次请求、90 秒期限及前端 120 节点 / 5 层上限不变。新增段落共享现有目标预算，不扩大抓取权限。人员关联和 topic 相似度只用于发现与排序。版权链接不是许可证兼容性判断，也不表示可以复用代码。

规则无法理解所有自然语言或代替源码分析；未能明确判断时展示原文并保留无向关系。验证局部上下文隔离、引用式 / HTML / 裸链接、版权与 Related、正反方向、否定与冲突、证据合并、缓存版本、箭头和既有手动展开 / 聚焦交互。结果写入 [验收记录](../acceptance.md)。
