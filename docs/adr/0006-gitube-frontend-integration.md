# ADR 0006：采用 Gitube 前端，共用会话与技术追溯服务

日期：2026-10-10。状态：已采纳。补充 ADR 0003 / 0004 / 0005，保留这些历史决定及后端实现。

## 来源与目标

用户提供 [Andy7016/Gitube](https://github.com/Andy7016/Gitube)，要求检查已有功能和风格，合入现有浏览器 GitHub 认证与追溯图谱。最初参考重建前的上游；2026-10-11 应用户隐私要求，由 [ADR 0007](0007-rebuilt-upstream-history.md) 将版本基线替换为重建版 `418daee527607dd0a97b1c8d675bf0a7a4895ecf`，停止保留旧提交链接。本 ADR 的功能设计继续有效；MIT 版权和许可证保留在 `gitube/`。

用户随后提出：领域内人尽皆知的高 Star 项目，不应仅因兴趣匹配与热度就总排在推荐前列。此问题先记录待调研，不在集成时凭经验改排序，详见 [调研记录](../recommendation-research.md)。

## 决定及理由

- 默认 Web 入口采用 `gitube/src/`，保留上游页面结构、频道、反馈、多收藏夹、深浅主题与快捷键。根 `src/` 和旧 Vite 配置保留，通过 `build:repoflow` 可恢复构建；做出此决定时目录尚无 Git 仓库，故保留原源码。后续 ADR 0007 建立了重建版历史，继续保留该恢复入口。
- 使用一个根 package 和既有 Express 进程，构建输出仍为根 `dist/`，站点与回调继续 `http://127.0.0.1:5173`。不沿用上游纯静态 Pages / Tauri 作为本次运行入口：服务端会话、凭据与追溯 Job 需要应用后端。
- 用同源 HttpOnly 会话替代上游浏览器持有 PAT 与开发期 OAuth 换 Token。现有本机 GitHub App 凭据不迁移、不改写；浏览器登录仍跳 GitHub，CSRF 与会话失效规则沿用既有服务。
- 在后端增加受限具名业务接口，保留前端推荐所需搜索语义与 DTO，避免开放任意 GraphQL 或通用带凭据代理。服务端实现可使用固定 REST / GraphQL，请求、批量和分页有边界，公开数据限制明确。
- 账号画像继续使用最多 1000 个历史 Star 和 300 个本人公开仓库的既有服务，叠加 Gitube 手选兴趣与站内行为；不退回仅最近 100 个 Star 的画像。
- 复用已验证的安全完整 README renderer 和一级追溯算法；路由、导航与 CSS 适配新界面，不重写图谱提取、证据、预算或排序。新增 `/repo` 并兼容旧 `/project` 地址；技术图谱保留独立 `/graph` 工作台。
- 不为“关注作者”增加 GitHub App 权限。原三连以实际支持的 Star、收藏、稍后再看组成，作者资料仍可外链访问。界面不能显示没有发生的关注。
- 无演示数据。移除上游登录页装饰仓库 fixture；封面若为仓库元数据驱动的生成图形，应视为装饰，不宣称它是真实贡献热力图。
- 本机实际绑定旧开发 API 端口 3001 返回 Windows EACCES；开发 API 与两个 Vite 入口统一改为可绑定的 5314。正式本地站点仍是 5173，注册回调不变；这个决定来自端口启动验证，与认证协议无关。

## 实现与验收

交界与范围见 [集成接口](../gitube-integration-contract.md)。后端验证业务输入、公开范围、分页、认证、CSRF、限流和不泄漏凭据；浏览器验证登录跳转、匿名真实检索、详情与完整 README、图谱自动 / 手动 / 独立入口、收藏与主题、返回导航、账号隔离和移动端。结果追加到 [验收记录](../acceptance.md)，不能以源代码完成代替运行验收。
