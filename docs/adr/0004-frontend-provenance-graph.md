# ADR 0004：在共享前端恢复有证据的技术来源图谱

日期：2026-10-13。状态：本次贡献采用，先在 fork 试用。

## 来源与范围演进

[Issue #3](https://github.com/Andy7016/Gitube/issues/3) 先记录了无服务端的图谱方案；[ADR 0003](0003-exploration-and-feed-resume.md) 对上一轮推荐功能的范围界定仍然有效。用户随后要求：若先前的图谱追溯可以由前端实现，就将它接入。此决定开启独立的图谱实现，不将上一轮的“仅方案”改写成已实现。

旧 `GithubImmersion` 的 `docs/graph-contract.md`、ADR 0008（分支布局与相机）、ADR 0012（工作区恢复）及相关测试作为行为参考。沿用 Gitube 的共享 React 前端和 GitHub 直接访问方式，不移植旧服务端任务队列、轮询接口、会话认证或磁盘缓存。

## 采集与证据

- 仅分析经 GitHub 元数据确认的公开仓库。浏览器用当前账号的 Token 向固定的 GitHub API 地址读取数据；证据链接供用户查看，不作为任意带凭据的请求地址。
- 真实公开仓库验收发现 README 经常保留迁移前的地址。REST 不跟随重定向；这类失败可在同一预算内通过固定 GitHub GraphQL 端点查询规范仓库名，避免将凭据转发到响应提供的地址。
- 读取原始 README 中的项目链接和局部语境，包括 Markdown、引用式链接、HTML 链接及来源段落中的裸链接。过滤当前仓库、导航、徽章和无效地址；保留原文、来源文件行号、目标和判断理由。
- 检查固定根目录依赖文件 `package.json`、`pyproject.toml`、`requirements.txt`、`Cargo.toml` 中明确的 GitHub 地址，不将包名猜测成仓库，也不安装或执行依赖。
- 人员证据来自公开贡献者、按 GitHub 优先级读取的 CODEOWNERS、README 明确列出的维护者及个人仓库所有者。贡献者不等同于维护者，组织和团队不猜成个人。仅有限抽样其公开自有仓库，按 topics 交并比呈现相关性；根仓库没有 topics 时可标明同语言候选，不伪造相似度百分比。
- `source` / `target` 记录采集路径。明确的上游或下游证据才产生“技术提供者 → 使用者”箭头；普通引用、版权致谢、人员重叠和主题相似本身不证明技术传承，冲突证据不强行决定方向。

## 预算与生命周期

为同时包含直接来源、依赖和人员线索，本次将 Issue 最初 README 阶段的 16 请求 / 60 秒预算扩展为每次分析最多 **48 次 HTTP、并发 3、单次 20 秒、总计 90 秒**。最多验证 12 个直接引用目标，扫描 2 位人员、每人至多 30 个公开自有仓库。404、失败和取消前已发出的请求也计入预算。达到限制即结束并展示部分结果与警告；不自动递归抓取。

详情页自动分析一层。独立图谱支持明确的手动展开，每次展开重新适用上述预算，整个工作区最多 120 个节点、深度 5。循环与共享节点合并，不通过后台无限递归补全。

同一 SPA 生命周期内按账号保留最多 8 个根工作区，包括图、展开状态、选择和相机。独立页最后访问的工作区与详情嵌入视图区分；普通返回恢复缓存，不重新请求。主动重新分析才刷新，失败保留上一份可用图。离开视图取消在途采集，账号或 Token 变化使旧请求和缓存失效。刷新应用不承诺恢复图谱，不新增持久化凭据或用户数据迁移。

采集结果显式区分运行失败导致的覆盖不完整与预先约定的抽样范围。首次分析可展示部分结果；已有图刷新时，即使根元数据成功、后续读取失败，也保留旧图及视角。部分展开可合并已获得的证据，并允许用户再次尝试，不将它标记为完成。

## 呈现与验收

使用确定性的原生 SVG，提供可键盘访问的节点列表和原文证据面板。相机平移、缩放、居中与“以此节点为根”是不同操作。节点面积表达真实 topics 相似度；空间布局表达展开分支，距离不解释为相似度。浅色、深色、窄屏都要可用，详情中的图谱不能无限撑长页面。

验收包括：来源解析与方向反例、公开仓库验证、请求预算与超时、取消和账号隔离、展开去重和深度限制、工作区返回不额外请求、刷新失败保留结果、恶意文本只作为文本、响应式显示，以及原有信息流恢复回归。实际结果与截图见[图谱验收记录](../acceptance/graph/README.md)。功能分支先推送个人 fork，生成新的预览与预发布版本；用户试用确认前不新建上游 PR。
