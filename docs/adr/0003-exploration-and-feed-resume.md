# ADR 0003：探索模式与推荐进度恢复

日期：2026-10-12。状态：本次贡献采用。补充 [ADR 0001](0001-following-weights.md) 和 [ADR 0002](0002-foreground-reading.md)。

## 来源与目标

在共享前端适配正常推荐、换换口味、完全随机，同时保留当前返回首页时恢复列表和滚动的能力。技术来源图谱另见 [Issue #3](https://github.com/Andy7016/Gitube/issues/3)，不在本变更内恢复图谱或服务端。

## 决定与理由

- 正常模式继续使用画像、热度、活跃度和社交候选；两种探索模式仍记录行为，但在真实候选池内随机选择，不采用画像分数或固定社交插槽。
- 换口味按手选兴趣展开且未屏蔽的 topics 对实际仓库分类，默认目标约一半熟悉方向、一半其他方向，短缺互补。比例集中为 `TASTE_FAMILIAR_SHARE = 0.5`，允许引擎参数实验；无可用手选兴趣时回正常模式。
- GitHub 没有全库随机接口，使用有界时间窗、Star 档位和排序变种召回，最多 3 轮、每轮 8 个搜索、每搜索 12 项，再洗牌。界面明确“候选池内随机”。三模式共用 Star、本人仓库、不感兴趣、屏蔽、归档和最近曝光过滤。
- 按账号、频道、推荐模式保存本次 SPA 运行中的列表、分页与滚动。首次访问检索，返回缓存恢复；换批只更新当前模式，完整刷新视为再次启动。兴趣/权重用于后续分页，不清空已有批次；屏蔽与已 Star 过滤即时生效。
- 恢复列表时重挂哨兵和程序滚动不触发分页。滚轮、触摸或非输入框内滚动键表达意图后恢复无限滚动；首次短列表可自动填屏。缓存被全部过滤时给明确空态。
- feed 请求代次、账号与当前模式共同判断有效性；引擎在本地副本推进游标，检查有效后再提交。切模式、换批、重置或切账号后的慢响应不能污染列表、游标、曝光和 seed 缓存。
- 保留正常模式旧游标键，其余模式单独存储。重置清理当前账号所有模式游标、反馈、权重和阅读去重，保留收藏、稍后再看、历史和手选兴趣。新增模式字段逐项验证，兼容 `version:1`。

## 验收

验证候选真实分类与短缺补足、随机排序独立于画像、共用过滤、模式/账号/游标隔离、失效请求不提交，以及恢复时请求次数与滚动。运行 `npm test`、`npm run build`；浏览器检查浅色、深色和窄屏。实际结果与限制见对应 PR。
